# Alert-to-Ref Jump Bridge

A bridge script that jumps directly from a GitHub Code Scanning alert to `shiori show --ref`.

## Overview

shiori can generate SARIF output with `--format sarif` and upload it to GitHub Code Scanning.
This recipe provides a workflow that looks up the original shiori ref from a Code Scanning alert
and displays the details (reason, owner, expiry, URL) with `shiori show`.

## Prerequisites

- [GitHub CLI (`gh`)](https://cli.github.com/) is installed
- Authenticated with `gh auth login`
- SARIF has been uploaded to the repository (see the CI configuration below)

## Usage

### From the command line

```bash
# Specify an alert number to display the ref information
./docs/recipes/alert-to-ref.sh owner/repo 42
```

### From a VS Code Task

Copy `docs/recipes/vscode-tasks.json.example` to `.vscode/tasks.json` and use it:

```bash
cp docs/recipes/vscode-tasks.json.example .vscode/tasks.json
```

Command Palette → "Tasks: Run Task" → select "shiori: Jump to ref from alert".

## How it works

1. Fetch the Code Scanning alert with `gh api`
2. Extract the ref from the alert message (`ID "..."` / `Ref "..."` patterns)
3. Run `shiori show --ref <ref>` to display the ref's details

### Ref extraction patterns

The messages generated by shiori's `verify` follow 2 patterns:

| Pattern       | Issue Types                                                        |
| ------------- | ------------------------------------------------------------------ |
| `ID "<ref>"`  | missing-in-registry, unused-in-source, expired                     |
| `Ref "<ref>"` | ref-format, unrouted-ref, ref-collision, registry-routing-mismatch |

The script extracts the ref from either pattern with the regular expression `(?:ID\|Ref) "\K[^"]+`.

> **Note:** `syntax-error` and `ref-format` messages do not contain the `ID "..."` / `Ref "..."` pattern,
> so automatic ref extraction fails (exit code 1). The error message shows the original alert message,
> so check the ref manually.

## Exit codes

| Code | Meaning                                          |
| ---- | ------------------------------------------------ |
| 0    | Success                                          |
| 1    | Ref extraction failed (message pattern mismatch) |
| 2    | gh CLI not installed                             |
| 3    | GitHub API authentication error (401/403)        |
| 4    | Alert not found (404)                            |
| 5    | Network error, etc.                              |

## CI configuration example

A GitHub Actions workflow that uploads SARIF to GitHub Code Scanning:

```yaml
# .github/workflows/shiori.yml
name: shiori
on: [push, pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    permissions:
      security-events: write
    steps:
      - uses: actions/checkout@v7
      - uses: pnpm/action-setup@v6
      - run: pnpm install
      - run: pnpm build

      - name: Scan annotations
        run: shiori scan > .config/shiori/scan-result.json

      - name: Verify and output SARIF
        run: shiori verify --format sarif > shiori.sarif
        continue-on-error: true

      - name: Upload SARIF
        uses: github/codeql-action/upload-sarif@v4
        with:
          sarif_file: shiori.sarif
```
