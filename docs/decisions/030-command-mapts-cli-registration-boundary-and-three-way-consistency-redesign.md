# ADR-030: command-map.ts CLI registration boundary and three-way consistency redesign

## Status

Draft (auto-generated by ADR Auto-Draft Pipeline)

## Context

command-map.ts は cli.ts の subCommandMap（全 CLI ラッパーへの参照マップ）と、doctor の三点一致チェック用 CLI_SUBCOMMAND_KEYS を export する。dependency-cruiser の Rule 3（commands-no-import-cli-wrappers）は command-map.ts を pure logic と見なすため、全 CLI ラッパーへの import が 32 件の違反として計上される。さらに doctor.ts が command-map.ts を dynamic import するため、3件の循環依存も発生し、合計 35 件の違反の根因となっている。

## Decision

command-map.ts を CLI 登録専用ファイルとして再分類する。(1) CLI_SUBCOMMAND_KEYS の export を command-map.ts から削除し、doctor.ts のランタイムチェックは REGISTERED_COMMANDS ↔ EXIT_CODE_POLICIES の二点一致に縮退させる。(2) 三点一致チェック（REGISTERED_COMMANDS ↔ EXIT_CODE_POLICIES ↔ Object.keys(subCommandMap)）はテストコード（exit-codes.test.ts）でのみ維持する。(3) dependency-cruiser Rule 3 の from.pathNot に command-map.ts を追加し、CLI 登録マップとしての本来の責務を認める。

## Consequences

ランタイムの doctor チェックは二点一致となり、subCommandMap との不整合はテスト実行時にのみ検出される。CI でテストが必ず実行されるため、実質的な安全性は維持される。command-map.ts に新コマンドを追加して REGISTERED_COMMANDS の更新を忘れた場合、テスト失敗として即座に検出される。
