# ADR-035: EP-0213 Badge コマンドの配置とガバナンス成熟度バッジ設計

## Status

Draft (auto-generated by ADR Auto-Draft Pipeline)

## Context

EP-0213 では shiori の成熟度スコアを SVG バッジとして README に埋め込む機能を求めている。既存の `report --format badge` は shields.io endpoint JSON を score ベースで生成する機構が完成しているが、EP-0213 は HealthMaturityStage（Foundation/Tracking/Maintained/Autonomous）ベースの色分けバッジを求めている。2つの独立した成熟度モデル（インフラ成熟度: MaturityLevel → MaturityStage と、ガバナンス成熟度: HealthMaturityStage）が共存しており、badge 出力における両者の関係を整理する必要がある。

## Decision

1. `shiori badge` を新コマンドとして追加するが、内部実装は `scan → report → buildHealthResult → formatReportAsBadge` パイプラインの薄いラッパーとする（check が verify のラッパーである既存パターンと同じ）。2. `ShieldsBadge` インターフェースに `governanceStage?: HealthMaturityStage` フィールドを追加し、既存の `stage?: MaturityStage`（インフラ成熟度）は後方互換のため保持する。3. maturityStage は `buildHealthResult()` から取得し、新たな結合は導入しない。

## Consequences

既存の `report --format badge` 消費者は影響を受けない（後方互換）。badge コマンドとreport --format badge が同じ出力を生成するため、出力の一貫性は保証される。将来的に2つの成熟度モデルの統合が検討される場合は、`governanceStage` フィールドをプライマリに昇格させる移行パスが取れる。
