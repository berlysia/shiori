# ADR-033: EP-0201 Next Steps type design: HealthNextStep as separate type from HealthPrescription

## Status

Draft (auto-generated by ADR Auto-Draft Pipeline)

## Context

EP-0201 adds a "Next Steps" section to the health command based on dual-axis quadrant analysis. The design question is whether to reuse the existing HealthPrescription type or create a new dedicated type. HealthPrescription is issue-driven (derived from ReportResult.byType), quantitative (scoreImpact as number), and tactical. NextSteps are pattern-driven (derived from Coverage/Hygiene quadrant), qualitative (rationale as string), and strategic.

## Decision

Create a new HealthNextStep interface rather than extending HealthPrescription. HealthNextStep includes priority, axis, message, command, and rationale fields. The rationale field replaces scoreImpact because quadrant-based recommendations are not quantitatively measurable in the same way as issue-based prescriptions. generateNextSteps() is placed in commands/health.ts (not core/prescriptions.ts) because it depends on health-command-specific context (quadrant patterns + prescription state). The scoreImpact axis decomposition (coverageImpact/hygieneImpact) is deferred to EP-0202 as a separate concern.

## Consequences

HealthResult gains an optional nextSteps field. JSON output includes both prescriptions (tactical) and nextSteps (strategic) as separate arrays. The init-specific NextStep type in next-steps.ts remains unchanged — different context, similar structure. Future commands (coach, weekly-report) that compose buildHealthResult automatically gain nextSteps.
