# ADR-034: EP-0204: Cumulative Fix Preview as separate function from planFix()

## Status

Draft (auto-generated by ADR Auto-Draft Pipeline)

## Context

EP-0204 requires showing cumulative impact of all prescriptions in `health --fix --preview` mode. The existing `planFix()` returns a single-prescription `FixPreview` by design (finds first automatable prescription). Extending `FixPreview` to handle multiple prescriptions would break the single-responsibility semantic of the existing type and require changes to `health-cli.ts` branching logic (L389-477).

## Decision

Add `planCumulativeFix()` alongside existing `planFix()` in `health-fix.ts`, returning a new `CumulativeFixPreview` type. This preserves the existing `planFix()` → `FixPreview` contract while introducing cumulative preview as a separate concept. Maturity stage prediction uses a `predictMaturityStage(coverage, hygiene, prescriptionCount)` helper that mirrors `classifyMaturityStage()` logic without requiring full `HealthResult` construction.

## Consequences

Two fix-planning functions coexist in `health-fix.ts`. Future unification (EP-0118 Phase 2) should consider whether `planFix()` becomes a special case of `planCumulativeFix()`. The `predictMaturityStage()` helper duplicates classification logic — if `classifyMaturityStage()` changes, both must be updated. Consider extracting shared logic into a `classifyFromAxes()` primitive in a future refactoring.
