# ADR-032: Phase 2 二軸スコアリング実装戦略: Coverage/Hygiene 分離と既存スコアの互換性維持

## Status

Draft (auto-generated by ADR Auto-Draft Pipeline)

## Context

ADR 024 で決定された二軸スコアリング（Coverage + Hygiene）の Phase 2 実装にあたり、既存の calculateScore() から新体系への移行戦略が必要。現在の calculateScore() は (1) DEDUCTION_TIERS による減点と (2) 候補比率ペナルティの2つのロジックを混合している。また HealthResult.health.score を参照する外部・内部コンシューマー（formatters, GitHub summary, snapshot, trend）が多数存在する。

## Decision

calculateScore() を calculateCoverage() と calculateHygiene() の2関数に分離する。Coverage = tracked/(tracked+candidates) の比率。Hygiene = 100 から DEDUCTION_TIERS の減点を適用（現 calculateScore のティア減点部分と同一ロジック）。Convenience score = min(coverage, hygiene) を新規関数 calculateConvenienceScore() として定義。既存の calculateScore() は非推奨マーカー付きで 1 リリース維持し、内部実装は calculateConvenienceScore() に委譲する。HealthResult.health に coverage: number と hygiene: number を追加し、score は min(coverage, hygiene) として後方互換維持。check-cli.ts の --coverage-threshold / --hygiene-threshold は Phase 2 scope に含める。

## Consequences

ReportResult と HealthResult の health フィールドが拡張される。既存の score フィールド消費者は修正不要（値の意味が「単一スコア」から「convenience score」に変わるが、数値範囲 0-100 は同一）。formatHealthSummary() は二軸プログレスバー表示に改修が必要。snapshot への coverage/hygiene 記録は EP-0193 として別途対応。
